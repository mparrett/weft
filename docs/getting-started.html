weft, in ten minutes

A durable graph of claims about work — what you are blocked on, what is blocked on you, and who is already on it.

Every command below was run in order against an empty store, and the output is what it actually printed. Node ids are content hashes, so yours will differ — weft resolves any unambiguous prefix, which is why seven characters is enough to paste around.

0. Build it

$ make
$ make install          # to ~/.local/bin
Build through the Makefile, not go build. The version is stamped through -ldflags, so a hand-rolled binary reports 0.0.0-dev and stops answering the first question you ask when something surprises you.

1. Find out where you are

Before writing anything, ask which store you are about to change. This is the only command that answers it, and it creates nothing.

$ weft env
version   0.1.0
store     /Users/you/.weft            (default)
log       /Users/you/.weft/log.jsonl  (not written yet)
actor     user:you                    (git config user.email)
ns        acme/api                    (git remote)
Why it names the rule, not just the value. The same path means different things depending on how it was chosen — $WEFT_HOME set in one shell follows you into the next repo. weft env also names any WEFT_* variable you have set that weft does not read, because a plausible-looking variable that does nothing is indistinguishable from one that works until you read the log.

2. Assert that work exists

A node says a unit of work exists. Most nodes have no issue tracking them and never will — that is the point.

$ weft add "N+1 in report generation" --kind bug --ref gh:acme/api#412
f46bc2b  N+1 in report generation  [acme/api]

$ weft add "cache invalidation race" --kind bug --source inferred
7f9341e  cache invalidation race  [acme/api]

$ weft add "batch export spec" --kind spec --ref file:docs/export.md
ca75891  batch export spec  [acme/api]

$ weft add "task 7: batch export" --kind task
b8723f9  task 7: batch export  [acme/api]
--source is doing real work here. The second bug was inferred by an agent, not reported by anyone. Roughly half a real graph is inference, and a graph that cannot separate observed from guessed stops being trusted. Values are asserted (default), observed, and inferred.
Nodes are append-only — there is no edit. Get --kind right at add time; fixing it means drop and re-add, which loses the node's edges. Refs are not in that trap: weft ref add and weft ref rm work on a node that already exists.

3. Connect them

$ weft link b8723f9 depends-on ca75891
b8723f9 depends-on ca75891

Six edge kinds: depends-on, conflicts-with, part-of, derived-from, supersedes, same-as. Only depends-on must stay acyclic — conflicts-with is symmetric and cyclic by nature.

4. Ask what you can actually start

$ weft ls
f46bc2b  bug   N+1 in report generation
7f9341e  bug   cache invalidation race
ca75891  spec  batch export spec
b8723f9  task  task 7: batch export

$ weft ls --ready
f46bc2b  bug   N+1 in report generation
7f9341e  bug   cache invalidation race
ca75891  spec  batch export spec

The task is gone from --ready: it depends on the spec, which is not done. Ask why rather than guessing.

$ weft why b8723f9
b8723f9  task 7: batch export

blocked by

  ca75891  spec  batch export spec
why prints the path, not the word "blocked". A bare status is not actionable. Readiness is optimistic and means "no known blocker" — never "safe to start".

5. Say you are on it

$ weft claim ca75891 --note "drafting the schema"
ca75891 claimed by user:you

$ weft ls --mine
ca75891  spec  batch export spec
Claims are advisory and do not lock. Two live claims on one node is a reported condition, not an error. Claims expire — the default TTL is 7 days — so weft ls --stale finds work someone took and never came back to. Use --holder to record that somebody else seems to be on something, with --source inferred.

6. Watch the frontier move

$ weft done ca75891
ca75891 done

$ weft ls --ready
f46bc2b  bug   N+1 in report generation
7f9341e  bug   cache invalidation race
b8723f9  task  task 7: batch export

The task is ready now, because its only blocker resolved. That is the whole loop: assert, connect, ask what is startable, record state, ask again.

why and ls --ready are only as good as the done states in the graph. On a graph where nothing is marked done, every node's nearest open blocker is one hop away and the answers look broken. They are not — record state as you go. Importing a repo is the fast way to seed it: weft import gh acme/api --merged-since 30d brings merged pull requests in as done alongside the open issues.

7. See the whole thing

$ weft show b8723f9
b8723f9  task  task 7: batch export
  ns     acme/api
  state  open
  source asserted, per user:you
  age    created just now, touched just now

  depends on
    ca75891  spec  batch export spec  (done)

One call returns a whole neighbourhood — deliberately, because if orienting takes five commands nobody orients. For the whole graph at once:

$ weft export --json | head -14
{
  "nodes": [
    {
      "id": "f46bc2b5021b6440a7794975a0cc27118a2458810a91372456fa844c3a1a7761",
      "ns": "acme/api",
      "kind": "bug",
      "title": "N+1 in report generation",
      "state": "open",
      "refs": [
        "gh:acme/api#412"
      ],
      "created": "2026-08-11T22:55:56.428699-07:00",
      "touched": "2026-08-11T22:55:56.428699-07:00"
    },

And to look at it as a picture:

$ weft view
Do not write your own renderer. weft view writes that same graph as one page with search, namespace scope, folding and layout, prints where it put it (--open opens it too), and keeps its view state in the URL fragment — so what you send someone is a link to the view, not a description of which dropdowns to set. It always carries the full export, so inferred edges draw differently from asserted ones, claims appear, and an observation shows its age. Add --only-ns acme/api when the page is going to leave your machine, and --self-contained when it has to draw without the network.

8. Where to go next

  • advanced-walkthrough.html — the same loop across two repositories, with the parts that only appear once several writers are involved: duplicate assertions and merge, blast radius, routes between two nodes, claims about other people, retractions, and what weft refuses to do.
  • weft help agent — the orientation snippet to paste into a project's CLAUDE.md. It ships with the binary, so it cannot drift from it.
  • SPEC.md — the data model, the query semantics, and the design constraints, with an appendix recording the prior art behind each decision.
  • EVENTS.md — the log format. Normative, and it wins on any conflict with SPEC.
  • BUILD.md — stack, layout, the measured performance budget, and the verification ladder.
The log is the contract, not the binary. Everything above is one append-only JSONL file. Other tools read it, agents parse it, and the graph is a fold over it — which is where history, audit and multi-writer support come from for free.
